## 一、项目概述

### 1.1 一句话定位

《经纬智造》是一款把古代花楼提花工艺转化为“可设计、可编译、可织造、可验证”交互体验的非遗文化教育软件。

用户在点阵画布中绘制纹样，软件把纹样转换为提花控制信息，生成花本与提升方案，再驱动虚拟经线、花楼、综片、梭子和筘完成织造，最终得到可检查的织物矩阵与图像。

### 1.2 项目不是什么

- 不是循环播放织布动画的视频播放器。
- 不是泛化的3D古风展厅。
- 不是只展示一张成品图的AI绘画工具。
- 不是专业纺织CAD的缩小版。
- 不是依赖联网大模型的聊天机器人包装。

### 1.3 核心价值主张

1. **文化价值**：用数字方式解释花楼提花机所代表的中国织造智慧。
2. **教育价值**：把“纹样—指令—执行—结果”转化为可观察的计算思维过程。
3. **技术价值**：实现可验证的映射链路，而不是伪造动画效果。
4. **传播价值**：让观众在一分钟内看懂“古代织机为什么像一台可编程机器”。

## 二、项目背景

### 2.1 文化背景

花楼提花机是中国传统织造技术的重要代表。工匠需要预先设计和保存纹样信息，再通过花本、花楼和提花机构控制经线提升，使不同颜色的纬线在经纬交织中形成图案。

它体现的不只是纺织工艺，还包含以下计算思想：

- 用离散信息表达连续图案；
- 用“花本”保存可重复执行的指令；
- 用机械结构读取并执行指令；
- 用稳定的流程降低重复劳动；
- 当纹样变化时，只需更改控制信息，而不必重做整套机械逻辑。

因此，提花工艺可以成为连接传统文化与现代计算机原理的天然教学入口。

### 2.2 现实问题

目前相关教育产品存在四类不足：

1. **展示偏静态**：观众只能看模型、图片或视频，看不到指令如何控制织机。
2. **专业工具门槛高**：现有织造设计软件面向专业人员，交互和概念超出中学课堂需要。
3. **原理与结果脱节**：很多作品展示漂亮成品，却不能解释纹样如何变成织造动作。
4. **文化和技术割裂**：文化类作品缺少计算逻辑，技术类作品缺少真实文化语境。

### 2.3 目标用户与场景

| 用户 | 需求 | 使用场景 |
|---|---|---|
| 中学生 | 直观理解信息编码和程序执行 | 信息科技、劳动教育、综合实践课 |
| 教师 | 用低成本软件完成一节课演示和练习 | 课堂投屏、分组操作、课后作业 |
| 博物馆观众 | 快速看懂提花机与成品之间的关系 | 展厅触摸屏、扫码下载、研学活动 |
| 非遗教育工作者 | 用可视化方式传播织造知识 | 工坊课程、线上科普、文化讲座 |

## 三、项目目标与边界

### 3.1 项目目标

1. 完成可独立运行的桌面软件，无需联网即可使用。
2. 建立“点阵纹样 → 花本指令 → 提花开口 → 织造成品”的完整数据链路。
3. 让每一步都能回看、解释和验证，避免只有视觉动画而没有逻辑依据。
4. 提供适合课堂和博物馆演示的引导流程。
5. 在19天内完成稳定版本、测试记录、演示视频与全套申报材料。

### 3.2 成功标准

- 用户可在 3 分钟内完成一次“绘制—编译—织造—导出”。
- 相同输入能够稳定生成相同织造结果。
- 编译结果、织造结果和预览图能够相互追溯。
- 核心算法具备自动化测试，关键映射不存在“看起来像”但不一致的实现。
- Windows 10/11 环境下，源码与打包版本均可运行。
- 至少完成一轮真实用户试用并保留反馈记录。
- 所有AI参与环节具备可披露的提示词、工具名称、输出记录和人工修改说明。

### 3.3 功能边界

**必须完成（P0）**

- 点阵绘图、擦除、清空、撤销和重做。
- 纹样校验与提花指令编译。
- 逐梭织造、自动播放、暂停和速度控制。
- 经线、综片/花楼、梭子和织物同步显示。
- 编织矩阵、织物预览与 PNG/WIF 导出。
- 示例工程、帮助说明和软件运行诊断。

**有时间再做（P1）**

- 更多颜色与多纬线模式。
- 纹样模板与挑战任务。
- 课堂讲解卡片和知识小测。
- 工程文件的缩略图预览。

**明确不做（P2）**

- 联网账号、云同步和排行榜。
- 实时控制真实织机。
- 照片级三维建模和复杂布料物理。
- 通用大模型聊天。
- 多人协作和在线课堂系统。

## 四、同类作品与差异化分析

### 4.1 同类方向

- 传统织造数字博物馆：重视模型和展陈，交互深度有限。
- 专业织造设计工具：功能强，但假设用户理解织造术语，不适合科普入门。
- 民族纹样AIGC作品：视觉生成强，却难以验证控制信息与成品之间的关系。
- 普通打地鼠式编程游戏：强调指令顺序，但缺乏真实文化工艺背景。

### 4.2 核心竞争力

本项目选择“小切口、深链路”：

1. 不只展示花楼提花机，而是让用户亲手完成一次从纹样到织物的编译。
2. 不只演示结果，而是把指令、提升方案、织造动作和成品放在同一界面中联动。
3. 不把AI当成装饰，AI只用于辅助开发、文案整理和测试设计，软件运行不依赖AI接口。
4. 可导出标准 WIF 织造交换格式，让古代提花逻辑能够连接现代数字织机流程。

## 五、创新点

### 5.1 纹样—指令—结果三重可追溯

每个织物像素都能追溯到：

- 原始纹样位置；
- 所在梭次；
- 对应提升指令；
- 经线/纬线交织结果。

用户既可正向观察织造，也可从成品反查某一梭的提花信息。

### 5.2 把“花本”解释为可执行程序

软件把连续相同的提花行合并为可复用指令，直观展示：

- 数据压缩；
- 指令复用；
- 状态机执行；
- 输入变化导致输出变化。

这比单纯说“古代机器很聪明”更具体，也更容易被计算机和信息科技教师接受。

### 5.3 不是动画，而是确定性模拟

织造结果由编译数据和状态推进计算得到。动画只负责表现状态变化，不负责伪造正确结果。

### 5.4 民族文化与现代科技的双向翻译

界面同时提供“工艺语言”和“计算语言”：

- 工艺语言：经线、纬线、花本、花楼、综片、梭子、打纬。
- 计算语言：输入矩阵、指令行、索引、状态、执行序列、输出矩阵。

### 5.5 可验证的成果输出

- 导出编织矩阵 CSV，便于核对每一步。
- 导出 WIF，连接现代织造软件工作流。
- 导出织物 PNG，用于申报材料和课堂展示。
- 保存 `.jwg` 工程文件，保留纹样、参数、编译结果和织造状态。

## 六、总体产品结构

软件采用“三步工作台”结构，始终围绕一条主线：

**设计纹样 → 编译花本 → 模拟织造 → 检查结果 → 导出成果**

### 6.1 点阵绘图面板

主要功能：

- 新建工程并选择画布尺寸。
- 使用画笔、橡皮、直线、矩形、填充等工具。
- 支持撤销、重做、清空和镜像。
- 显示行列坐标、当前纹样尺寸和有效纹样数量。
- 提供示例纹样和空画布两种入口。

输出：

- `PatternGrid`：二维离散矩阵。
- 校验结果：是否为空、是否存在无法织造的行、是否需要压缩。

### 6.2 纹样编译模块

主要功能：

- 将纹样按纬向切分为提花行。
- 合并相同提花行，生成花本指令。
- 为不同提升组合分配花本编号。
- 生成每一梭的提升集合、综片/花楼动作和投梭顺序。
- 显示编译报告：原始行数、压缩后指令数、压缩率、可能风险。

输出：

- `WeavePlan`：可执行的织造计划。
- `CompileReport`：用于教学解释和问题定位的编译日志。

### 6.3 织造模拟预览模块

主要功能：

- 以侧视/半剖面方式展示花楼、经线、综片、梭子和筘。
- 按梭次展示提升、开口、投梭、打纬。
- 单步、连续播放、暂停、回退和速度调整。
- 同步更新织物形成区域。
- 发生错误时显示具体梭次和原因。

输出：

- `LoomState`：织机当前状态。
- `WeaveMatrix`：已经形成的织物矩阵。
- 实时预览与最终成品图。

### 6.4 教学解释模块

- 每一步用一句“正在发生什么”解释动作。
- 用“工艺语言”和“计算语言”双栏对照。
- 提供编译压缩率和映射关系提示。
- 不引入复杂知识图谱或联网助手。

### 6.5 本地工程管理

- 保存和打开 `.jwg` 工程。
- 自动保存最近状态，异常退出后可恢复。
- 内置示例工程和帮助页。
- 记录软件版本、运行环境、导出路径和异常日志。

## 七、整体UI与交互逻辑

### 7.1 主窗口结构

采用顶部导航 + 左侧工具区 + 中央工作区 + 右侧属性/解释区 + 底部状态时间轴。

```text
┌──────────────────────────────────────────────────────────────┐
│ 项目名 | 新建 打开 保存 | 设计 编译 织造 | 导出 | 帮助        │
├──────────────┬──────────────────────────────┬────────────────┤
│ 工具与参数   │        当前工作画布          │ 属性/解释/报告 │
│              │                              │                │
├──────────────┴──────────────────────────────┴────────────────┤
│ 状态栏 | 当前步骤 | 进度 | 错误提示 | 版本                      │
└──────────────────────────────────────────────────────────────┘
```

### 7.2 交互状态机

1. **空状态**：新建或打开示例。
2. **设计状态**：绘制纹样，实时标记可编译性。
3. **待编译状态**：修改纹样后提示“结果已过期，需要重新编译”。
4. **已编译状态**：允许进入织造；显示花本指令和压缩报告。
5. **织造中**：禁止直接修改纹样，只能暂停、单步或返回设计。
6. **已完成状态**：允许导出、回放和生成讲解报告。

### 7.3 视觉语言

- 主色：靛青、朱砂、米白、墨色。
- 风格：传统织造图谱与工程蓝图的结合。
- 不使用过度写实木纹和复杂3D材质，保证跨设备稳定运行。
- 所有关键状态都同时使用文字、形状和颜色表达，避免只靠颜色传递信息。

### 7.4 错误与恢复

- 编译失败：停留在设计页，指出具体纹样行。
- 模拟异常：保留最后稳定状态，提供回到上一梭的按钮。
- 导出失败：给出目标路径、可能原因和重试入口。
- 工程版本不兼容：提示版本信息，不静默覆盖原文件。

## 八、技术方案

### 8.1 技术选型

- 语言：Python 3.14。
- GUI：PySide6 6.11.x，采用 Qt Widgets、QGraphicsView/QGraphicsScene 和 QPainter。
- 测试：Python 标准库 `unittest` 或 pytest，优先保证核心算法可测试。
- 数据：JSON 工程文件，PNG、CSV、WIF 导出。
- 打包：PyInstaller，生成 Windows 免安装目录或单文件程序。
- 运行环境：离线运行，不依赖外部服务器和浏览器。

选择 PySide6 的原因：

1. 桌面控件、画布、动画和文件对话框成熟，适合复杂工作台。
2. 比 Pygame 更容易实现可访问、可维护的表单和面板。
3. 比 Tkinter 更适合长期维护和高质量视觉表现。
4. PySide6 6.11.2 已确认支持 Python `<3.15`，当前 Python 3.14 满足要求。
5. PyInstaller 6.22.3 已确认支持当前 Python 版本，打包路线可行。

### 8.2 分层架构

```text
表现层 presentation
  MainWindow、设计面板、编译面板、织造面板、预览面板

应用层 application
  ProjectService、CompileService、SimulationService、ExportService

领域层 domain
  PatternGrid、WeavePlan、Pick、LoomState、WeaveMatrix、CompileReport

基础设施层 infrastructure
  工程读写、PNG/WIF/CSV 导出、路径管理、日志

测试与工具
  unit tests、golden files、兼容性检查、打包脚本
```

### 8.3 核心数据模型

- `PatternGrid`：纹样矩阵，值为颜色索引或布尔提升状态。
- `LoomConfig`：经线数、纬线数、综片数、循环模式和织造方向。
- `Pick`：一梭的提花信息，包含提升线程集合和花本编号。
- `WeavePlan`：按顺序排列的全部 `Pick`。
- `LoomState`：当前梭次、开口状态、纬线位置和已完成矩阵。
- `WeaveMatrix`：最终经纬交织结果。
- `CompileReport`：输入摘要、压缩统计、警告和错误。

### 8.4 核心算法

1. 校验纹样矩阵的坐标和值域。
2. 将纹样按纬向切分为行。
3. 对每行提升模式进行规范化并计算哈希。
4. 合并相同行，生成花本指令表。
5. 为每次织造分配花本编号和提升集合。
6. 按“提升—开口—投梭—打纬”推进状态。
7. 根据经纬状态生成织物矩阵。
8. 将矩阵与每一步的状态进行一致性校验。

## 九、数据、历史与版权规范

### 9.1 历史准确性

软件展示的是“教学化原理模型”，不是对某一具体历史型号的工程测绘。所有涉及历史名称、结构和工序的说明都必须附来源记录，区分：

- 有公开文献支持的史实；
- 为教学简化的模型；
- 艺术化视觉表达。

### 9.2 素材规范

- 不直接复制来源不明的民族纹样、照片、字体和音乐。
- 示例图案优先使用团队原创的几何纹样，并在说明中标注设计来源。
- 若使用第三方素材，必须记录作者、许可协议、下载地址和修改情况。
- 字体优先使用系统字体；如打包第三方字体，必须使用允许再分发的开源许可证并保留许可证文件。

### 9.3 民族文化表达边界

重点表达“中华民族织造智慧”和“工艺如何被数字化理解”，避免把民族文化简化为符号拼贴，不虚构民族习俗，不擅自使用具有特定礼仪或信仰含义的图案。

## 十、AI工具使用策略

### 10.1 软件运行时不调用AI

为了保证比赛演示稳定，软件本体不依赖外部大模型接口。AI只用于开发辅助和材料整理。

### 10.2 AI参与环节

可能包括：

- 项目框架和文档草稿整理；
- Python模块结构设计；
- 单元测试用例生成；
- 演示视频脚本初稿；
- 申报材料语言润色。

### 10.3 必须留档的信息

每项AI参与记录应包括：

- 工具名称和版本；
- 使用日期；
- 输入提示词或工作流摘要；
- AI输出摘要；
- 人工筛选、修改和最终采用情况；
- 未采用内容及原因。

记录目录建议为 `docs/ai-log/`，最终汇总为比赛要求格式的《人工智能工具使用情况说明》。

## 十一、测试与质量方案

### 11.1 单元测试

- 矩阵尺寸和值域校验；
- 相同提升行合并是否正确；
- 花本编号是否稳定；
- 每一梭的提升集合是否与原始纹样一致；
- 织物矩阵是否可按规则复现。

### 11.2 属性测试

- 任意合法输入经编译后再解码，提升集合应一致。
- 修改一个纹样单元只应影响声明的目标区域。
- 保存后重新打开，工程关键数据应完全一致。

### 11.3 集成测试

- 新建→绘制→编译→织造→导出全流程。
- 连续编辑后撤销/重做。
- 暂停、继续、单步和回退。
- 无效纹样和损坏工程文件的错误处理。

### 11.4 兼容性测试

- Windows 10 与 Windows 11。
- 100%、125%、150% 显示缩放。
- 源码运行与 PyInstaller 打包运行。
- 无网络、低分辨率、不同DPI和常见输入尺寸。
- 中文路径、空格路径和只读目录的导出处理。

## 十三、主要风险与应对

## 十五、作品简介（申报初稿）

《经纬智造·花楼提花机的可编程密码》是一款面向中学信息科技教育和博物馆科普的桌面交互软件。作品以中国传统花楼提花工艺为文化载体，将纹样设计、花本编译、提花开口、投梭打纬和织物生成连接成完整闭环。

用户可以在点阵画布中绘制纹样，软件将纹样自动编译为花本控制信息，模拟经线提升、花楼动作和梭子穿行，并逐梭生成织物预览。作品不是单纯的动画播放器，而是强调“纹样到指令再到织造结果”的可验证映射，让观众直观理解提花机如何保存和复用信息，以及它与现代可编程机器之间的思想联系。

软件采用无网络依赖的桌面应用形式，包含工程设计、编译报告、织造模拟、成果导出和教学解释等模块，并可导出 WIF 织造交换文件。通过亲手设计、执行和检查，用户可以同时学习民族文化、织造原理和信息编码，体会传统工艺中蕴含的计算智慧。

## 十六、创意来源（申报初稿）

花楼提花机用花本记录和传递复杂纹样信息，这种“预先编码、机械读取、重复执行”的方式，与现代程序将逻辑保存为指令并由机器执行的过程高度相通。团队希望把这一历史智慧从静态展板和成品图片中解放出来，让观众看见信息如何控制机械、机械如何形成织物，并理解传统工艺并非与现代计算机无关，而是包含着早期可编程思想。

## 十七、运行环境（申报初稿）

- 操作系统：Windows 10/11 64位。
- 处理器：双核及以上。
- 内存：4GB及以上，推荐8GB。
- 显示：1366×768及以上。
- 磁盘：预留500MB。
- 网络：核心功能无需网络。
- 输入设备：鼠标和键盘。

## 十九、当前决策

1. 采用“设计—编译—织造—导出”单一主链路，不以泛3D展厅作为核心。
2. 采用 PySide6 作为桌面GUI，保证控件、画布和打包路线清晰。
3. 核心织造逻辑保持离线、确定性、可测试。
4. 删除通用聊天机器人和联网依赖。
5. 将“民族文化表达”落实为有来源、有语境、可解释的织造知识，而不是符号堆叠。
6. 先完成P0，任何新增功能必须经过项目负责人评审，不能影响10月23日提交。
